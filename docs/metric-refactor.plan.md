## 事实与来源（口径以用户 2026-10-20 口述为准）

- 链路：业财在术加平台用**指标计算功能**写 SQL；指标 code 配置时选定；写入时术加平台按 code **运行时调用指标平台 API** 取 code+id，拼接入 INSERT，目标表多出编码、ID 两列 / 用户口述
- 规模：业财 **780+ 指标**（≈780+ 条逻辑规则）/ 用户口述
- 事故：指标平台 API 故障 → 业务中断；**多年仅一次**（最近一次即本次整改起因，不写具体时间）；该能力**平台内化，我方无快恢手段** / 用户口述
- 整改依据：指标平台**底表**将进维度数据（来源=指标平台+MCA），经 **PUB 统一调度**刷新（不定期，不受我方控制）/ 用户口述
- 方案：术加平台功能切换（指标计算→**数据加工**）+ SQL 增加关联维表取编码/ID；**目标表结构与下游取数完全不变** / 用户口述
- 新风险：刷新不及时 → 目标表编码、ID 两列**空值**；可配套 **DQ 校验（建议项）**查空值；空值**无法即时修复**，需待 PUB 刷新后重跑补偿，时效不可控 / 用户口述
