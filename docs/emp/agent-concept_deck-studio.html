设计开发阶段：方案与架构

Agent 自己跑流水线，人只在闸口拍板——
从 RS+US 到五件套制品（DDL/术加/调度/DQ/集成），一段流程、一份 spec、两个闸口。

主题：设计开发的人机交互 · 展开讲协同与场景2026
01 / 形态
形态：一条流水线，人在闸口决策
吃 RS+US（需求spec+用户故事），吐五件套制品（DDL/术加/调度/DQ/集成）。UT 是收尾工序，代码稳定后交付下游。
02 / 场景
场景：新建与优化，共用一条主干
差异只在"进入IT设计前怎么拿到spec"。优化时 RS和现状spec 并行产出、串行合并。优化只精确修改。
03 / 协同
协同：与上下游靠 spec 交接，制品推到各平台
多个专业 agent 靠 spec 交接。读用 MCP 连，制品推到对应平台开发环境运行。下游接测试Agent。
04 / 机制
机制：与开发环境螺旋迭代，直到稳定
不是"造完交付走"，是螺旋迭代：改→部署开发环境→跑→捞结果→改。代码稳定（agent判）+ 数据准确（人判），两层分开。
05 / 全貌
能力矩阵：这个 agent 由什么构成
纵轴=实现种类（Skill/Command/Protocol/MCP），横轴=战略层次。核心居中，基础在左，增强在右。格子高度=投入量。
