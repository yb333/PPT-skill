# process.md — 协作流程深度规范（Phase 1 / 2 / 5 背后的纪律）

吸收自 AICO-PPT workflow.md 并适配 deck-studio（无模板体系）。总原则：**确认闸门是硬的**——没拿到用户明确确认不进下一阶段；返工最大来源就是跳过需求/大纲直接搭页。

## Phase 1 深度：需求共识五件事

用户往往一句话提需求。先从对话和材料提取以下五件；已有答案不重复追问，影响主线的缺项**一次问完**，不挤牙膏：

1. **听众是谁**：背景、人数、对主题熟悉度（决定深度与术语量）
2. **场合与时长**：授课/汇报/自读？现场讲还是发出去看？多少分钟？（对照场景适配表定基调）
3. **讲完想达成什么**：听众离场该记住/会做什么（决定主线）
4. **已有素材**：文档、数据、截图、旧 PPT、外链（决定哪些页有真料）
5. **品牌与交付**：默认蓝板还是选风格（Phase 3）；交 HTML 还是 PPTX

产出：五点整理成一段**需求共识**复述给用户确认，不脑补。

**用户催"时间紧直接做"**：压缩成**带默认值的一轮快答**——每件事给默认假设，用户只需纠偏（"都对"即开工）。加速的是讨论形式，不豁免闸门。

## 先整理材料中的事实（定主线之前）

读完材料再定主线，不能先选版式再找文字填满。围绕听众需要的判断提取**工作对象、具体做法、结果、可复用产物、后续安排**；不是每份材料都要上页。

- 入选主张按 `主张 / 对象与状态 / 原始数值和口径 / 来源位置` 记入 plan.md 的"事实与来源"；有现成清单直接复用，不重复造台账。保留具体文章、工具、平台名称与入口，别抽象成"知识、工具、培训"
- 分清**已完成成果 / 进行中探索 / 后续建议**，以及**本项目新增 / 既有积累 / 外部资源**。做过一次验证≠成熟能力；资产库规模≠本项目产出
- 能从材料定位的信息自行补全；仍影响标题结论/成果归属/执行安排的缺项并入需求/大纲讨论询问。**未确认的负责人、日期、收益、覆盖率、资产名称不得编造**

## 场景适配表（定基调的权威依据）

| 维度 | 授课/培训 | 汇报（进展/方案/述职） | 学习材料（自读） |
|---|---|---|---|
| 叙事骨架 | 抛问题→讲原理→看实践→巩固收尾 | **结论先行**：背景一页→结论/诉求→论据数据→风险与下一步 | 手册式：总览→分主题逐节→速查小结 |
| 页数节奏 | 1.5–2 分钟/页（40 分钟≈20–25 页） | 用时间**一半**做页数预算（10 分钟≈5–8 页），留一半问答；备查进附录 | 不受时长约束，按主题完整性；单页密度可更高 |
| 动画用量 | 按讲课节拍整拍设计（编排层可用） | 少用——常被打断、常导 PPTX 静态翻阅 | 基本不用（无讲者推进，读者滚动） |
| 语言风格 | 口语化、类比、设问可用；细节由讲者展开 | 书面结论化：判断句+量化数字（写"提升 1.76×"不写"快了很多"）；不用生活类比/设问 | 完整自解释句子，不依赖讲者在场；忌电报式短语 |
| 交付形态 | HTML 放映为主 | PPTX 常是硬要求——**初版就先试导一次**，转换问题早暴露 | HTML 单文件分发 |

## 按章规划：先分章，再排页

deck 不是页的堆栈。大纲确认前先分章：**3–6 章，每章 2–5 页**，每章回答一个子问题；页一律挂到章下，不允许"随手加一页"。≥7 页的 deck 第 2 页放**目录页**（页型见 page-types.md），条目 = 章级，序号与各页 eyebrow 的 `章.节` 编号（如 `2.1 · 流转`）一致——观众任何时候对得上"讲到第几章"。

- 结构变动（增删章、挪页）先改章再改页：目录条目、受影响页的 eyebrow、页码范围**同批更新**，不许只动一处
- 一页挂不进任何章 → 大概率离题，回主线检查，而不是硬塞或放任
- 章名与章序在需求共识时一并确认，属于大纲闸门的一部分

## plan.md 落盘（防丢的伴生文件）

大纲确认后立即写成 `<deck名>.plan.md`，**别只留在对话里**（换会话/换人就丢）。不要长——章级几行 + 每页一行：

```markdown
# 演示名 · 页面规划
## 大纲
- 01 章名 — 本章要回答的问题（N 页）
## 逐页（生成后随改随更）
| # | label | 这页要说啥（一句话） | 布局 | 配图 |
## 事实与来源
- 主张 / 对象与状态 / 原始数值和口径 / 来源位置
```

这个文件是讲稿骨架和跨会话修改依据，Phase 5 改页随手同步它。

## 按页面要回答的问题组织内容

先定每页的信息任务再定维度。成果/能力沉淀汇报参考：

| 页面任务 | 组织顺序 | 避免的写法 |
|---|---|---|
| 形成了什么能力 | 交付场景 → 可重复的方法/机制 → 代表结果 → 沉淀去向 | 只列工作活动或技术栈；"完成验证"当能力名 |
| 留下什么可复用资产 | 沉淀方向 → 承载形式 → 具体条目与代表实例（有入口带入口） | 只有抽象分类 |
| 接下来怎样推进 | 延续前页能力/资产 → 目标场景与差距 → 具体行动 → 责任与验收 | "补齐、统一、验证、推广"通用动词堆砌 |

跨页检查：后页接住前页的对象，每页新增一类回答；与主线无关的探索放备查或删。具体产物清单比泛化说明有用；精简的是低价值表述，不是机械减字。

**每页核心观点写不成一句话 → 该拆页；两页同一句 → 该合。**

## Phase 5 深度：讨论与修改纪律

- 给用户看 deck 前**先自检**（下方清单），不把明显文字/组织问题留给用户发现
- **逐章引导反馈**，别只问"你看看怎么样"：每章问"这章观点顺序对吗？哪页要增删？"
- 意见**按页记录**成修改清单，改完逐条回报（改了什么、在哪页、门禁是否过）
- 结构性意见（挪章、删线索）在初版轮消化——**终版只做精修**，结构性返工回到初版轮重新过闸门，否则"终版"无限循环
- 每次修改后跑机器门禁（SKILL.md Phase 5 命令）；交付前加跑导出保真门禁（export_check，SKILL.md Phase 5 ⑤）——溢出裁切是无声的，用户看到的比你以为的少一截

## 内容自检清单（初版与终版共用）

修改已有 deck 时只查受影响页及关联事实，沿用已确认口径，不重写无关页面。

- **主线与实体**：标题连读成论证链；每页回答不同问题；能力有方法与证据、资产有具体产物、计划有目标对象和可执行动作；未知项没写成既定承诺
- **数字与命名**：回源核对数值、分母、单位、基线与状态；同一工具/平台用核实过的名称，保留原始标识符，不合并相近名字；查错字
- **删字检查**：见 copywriting.md——遮住可删的就删，影响口径的随结论就近呈现
- **内容与画面**：主要阅读空间留给证据、具体资产和行动；表格/截图关键内容在目标观看尺寸可读

## 常见错误对照表

| 错误 | 纠正 |
|------|------|
| 跳过需求/大纲直接搭页 | 返工最大来源；催"直接做"改带默认值快答，不跳闸门 |
| 大纲/规划只留在对话里 | 确认后落盘 plan.md，每页一行不要长 |
| 页不挂章、随想随加 | 先分章再排页（3–6 章）；结构变动时目录/eyebrow/页码范围同批更新 |
| 拿授课节奏做汇报 | 20 页塞 10 分钟必翻车：页数减半、结论先行、细节进附录 |
| 给自读/汇报堆动画 | 无讲者推进就是障碍（见场景适配表） |
| 页面写"点击查看"类操作提示 | 删（真实功能按钮标签除外） |
| 语言风格与场景错位 | 按场景适配表校全文 |
| 栏目式/悬念式标题 | 改成观点判断句 |
| 成果页写成通用建议 | 回材料提取真实产物、名称与代表实例 |
| 一页塞多个核心观点 | 写不成一句话就拆页 |
| 初版就抠图、精调动画 | 结构没定精修全是沉没成本；结构讨论用文字+简图即可 |
| 只问"你看看怎么样" | 收不到可执行反馈；逐章提具体问题 |
| 改完不跑门禁就给用户 | 溢出是无声的 |
| 终版阶段接受结构性返工 | 回初版轮重新过闸门 |
