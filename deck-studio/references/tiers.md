# tiers.md — 能力分级与降级通道

面向的模型与 agent 能力各不相同。本 skill 把 deck 拆成**固定件**（脚手架/chrome/引擎/编辑器/封面，全部脚本预制，见 D11）与**内容件**（文案/版式/图示）——降级只发生在内容件与验收步骤，固定件在任何档位都由脚本保证正确。

档位判定不靠模型自评（普遍高估），靠 `scripts/probe.mjs` 机械化探测 + 宿主视觉声明（`AICO_VISION=1` 或 `--vision`）。**开工前先跑探针，按输出档位执行对应规则。**

## 两档规则

| | vision（有视觉） | novision（无视觉） |
|---|---|---|
| 目检（shot 逐页看图） | ✅ 必做 | ❌ **禁止**——机器门禁照跑，目检步骤显式跳过并在交付说明中告知用户自行查看 |
| 自由 SVG 自绘（svg-diagrams.md 全流程） | ✅ | ❌ 降级为**简单版式**：流程条 / 对比两栏 / 表格混排 / 卡片网格；确需复杂图示时产出后标注「复杂图示待视觉模型/用户补充」 |
| 内容共建 / 文案 / 结构 | ✅ | ✅（对话照常） |
| 机器门禁（sync / overflow / e2e / export_check） | ✅ | ✅（确定性脚本，不需要视觉） |
| 固定件（init-deck / 编辑器 / 引擎） | ✅ 脚本保证 | ✅ 脚本保证 |

工具链不全（node/playwright/python 缺失）时：仅 init-deck 骨架产出 + 填内容，门禁与导出明确告知用户在本地运行。

## 设计依据

- 降级的单位不是"质量打折"，而是"砍掉哪些步骤、交给谁兜底"：视觉步骤交给用户，图示降级为版式，固定件交给脚本。
- 参数化 SVG 片段库（只换文字标签的预制骨架）是 novision 档未来解锁复杂图示的方向——按需沉淀，遇一个真实场景收一个，不预先铺量。
